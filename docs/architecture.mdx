## Request flow — patient verification

```
Nurse opens verification screen
        │
        ▼
Flutter captures fingerprint image
        │
        ▼
POST /api/fingerprint/verify (multipart image + patient_id)
  Authorization: Bearer <sanctum-token>
        │
        ▼
Laravel validates token, role (nurse), hospital scope
        │
        ├── load stored ORB template from DB
        │
        ▼
POST http://python-service:5001/process-fingerprint (image file)
  X-Internal-Api-Key: <shared secret>
        │   returns quality_score + ORB features
        ▼
POST http://python-service:5001/match (probe features + stored template)
  X-Internal-Api-Key: <shared secret>
        │   returns score + verdict
        ▼
Laravel checks score against FINGERPRINT_MATCH_THRESHOLD (default 32.0)
        │
        ├── on MATCH  → fetch EHR + insurance from GoT-HoMIS
        ├── on NO MATCH → increment failure counter, lock after 5 fails
        │
        ▼
JSON response → Flutter displays result screen
```

<Note>
  Hospital-wide identification (unknown patient) now goes through `POST /api/verify/multimodal` (face shortlist → fingerprint confirm) or `POST /api/verify/hand` (four-finger fused). The legacy `POST /api/verify` is deprecated but kept for backward compatibility — see [Verification](/api-reference/verification).
</Note>

## Database schema (key tables)

```
hospitals
  id, name, address, wifi_ssid, lat, lng, radius_meters, face_recognition_enabled

users (staff)
  id, hospital_id, name, username, email, role, is_active

patients
  id, hospital_id, full_name, date_of_birth, gender, jmbg, phone, is_active

fingerprints
  id, patient_id, hospital_id, enrolled_by (user_id),
  template (JSON — ORB keypoints + descriptors, AES-256 at rest),
  finger_position, quality_score, is_primary, is_active,
  failed_attempts, locked_at

face_templates
  id, patient_id, hospital_id, enrolled_by (user_id),
  template (512-dim embedding, AES-256 at rest),
  quality_score, created_at
  — oldest row auto-evicted when per-patient cap is reached

verification_logs
  id, patient_id, hospital_id, staff_id, verdict, score, modality (fingerprint|face), ip_address

audit_logs
  id, staff_id, hospital_id, action, patient_id, ip_address, user_agent, meta (JSON)
```

## Security layers

1. **Sanctum token** — 8-hour expiry, revoked on logout, single active token per user
2. **Role middleware** — `role:nurse,admin` checked before every sensitive route
3. **Hospital scope** — `hospital.access` middleware blocks cross-hospital data access
4. **Geofence** — Flutter checks GPS + WiFi SSID before allowing capture; backend re-validates via the `geofence` middleware, failing closed in production (`GEOFENCE_FAIL_OPEN=false`)
5. **Internal service key** — Laravel ↔ Python calls carry a shared `X-Internal-Api-Key`, required in production
6. **Fingerprint locking** — 5 failed attempts within 1 hour locks the record
7. **Template encryption** — ORB feature JSON encrypted at rest (AES-256)
8. **No raw image storage** — only processed feature templates are persisted

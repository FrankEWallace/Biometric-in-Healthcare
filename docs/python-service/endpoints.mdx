# Python service endpoints

Base URL: `http://localhost:5001` (internal only)

Interactive docs: `http://localhost:5001/docs`

<Note>
  Every route below except `/health` requires the `X-Internal-Api-Key` header when `INTERNAL_API_KEY` is configured on the Python side. See [Security](/security#internal-service-authentication-a-known-gap).
</Note>

---

## GET /health

Liveness probe. Returns immediately.

**Response**

```json
{ "status": "ok" }
```

---

## POST /process

Extract a SourceAFIS-style minutiae template from a base64-encoded fingerprint image (`contact` domain, single finger). Runs the full preprocessing pipeline (grayscale, blur, equalization, adaptive threshold, morphological thinning) before extraction.

**Request body**

```json
{
  "image": "<base64-encoded JPEG or PNG>"
}
```

**Response**

```json
{
  "template": {
    "minutiae_count": 128,
    "status": "ok",
    "format": "minutiae_v1",
    "minutiae": [...]
  },
  "quality_score": 0.42
}
```

The returned `template` is opaque to callers; pass it unchanged to `POST /match` as a probe or candidate template.

**Errors**

| Status | Reason |
|---|---|
| 400 | `image` is empty or invalid base64 |
| 400 | Image bytes could not be decoded as JPEG/PNG |

---

## POST /match

Match a probe minutiae template against a list of candidate templates. Returns the best-matching `patient_id`. Score is a **raw SourceAFIS-style float, typically 0-200+**. This endpoint does not apply a verdict; the caller (Laravel) compares against the shared `FINGERPRINT_MATCH_THRESHOLD`.

**Request body**

```json
{
  "probe": { "minutiae_count": 128, "status": "ok", "format": "minutiae_v1", "minutiae": [...] },
  "candidates": [
    {
      "patient_id": 1,
      "template": { "minutiae_count": 112, "status": "ok", "format": "minutiae_v1", "minutiae": [...] }
    }
  ]
}
```

**Response**

```json
{
  "patient_id": 1,
  "score": 34.5
}
```

**Errors**

| Status | Reason |
|---|---|
| 400 | `candidates` list is empty |
| 400 | No valid candidates could be processed |

## POST /process-fingerprint

Full preprocessing + minutiae extraction pipeline for a multipart-uploaded fingerprint image (the `contact`-domain endpoint `FingerprintController::register`/`enroll` calls).

**Request:** `multipart/form-data`

| Field | Type | Required |
|---|---|---|
| `file` | JPEG or PNG upload | Yes |

**Response**

```json
{
  "success": true,
  "message": "Image processed successfully.",
  "filename": "finger.jpg",
  "quality_score": 0.55,
  "steps_applied": ["grayscale", "blur", "equalization", "threshold", "thinning"],
  "processed_image": "<base64 PNG of skeleton>",
  "features": {
    "minutiae_count": 128,
    "status": "ok",
    "format": "minutiae_v1",
    "minutiae": [...],
    "keypoint_count": 128
  }
}
```

`features.keypoint_count` is an alias of `minutiae_count`, kept for backward compatibility with earlier callers.

**Errors**

| Status | Reason |
|---|---|
| 400 | Unsupported file type (not JPEG/PNG) |
| 400 | Uploaded file is empty |
| 400 | Image could not be decoded |

## POST /match-fingerprint

Compare two uploaded fingerprint images end-to-end (preprocess + extract + match both) and return a MATCH / NO MATCH verdict. Used primarily for standalone testing; production enrollment/verification calls `/process-fingerprint` and `/match` separately so Laravel can store/retrieve templates between calls.

**Request:** `multipart/form-data`

| Field | Type | Required |
|---|---|---|
| `image1` | JPEG or PNG upload | Yes |
| `image2` | JPEG or PNG upload | Yes |

**Response**

```json
{
  "verdict": "MATCH",
  "score": 34.5,
  "image1": {
    "filename": "probe.jpg",
    "minutiae_count": 128,
    "feature_status": "ok"
  },
  "image2": {
    "filename": "stored.jpg",
    "minutiae_count": 112,
    "feature_status": "ok"
  }
}
```

**Verdict threshold**

`score >= MATCH_THRESHOLD` (env `FINGERPRINT_MATCH_THRESHOLD`, default **32.0**) returns `MATCH`, otherwise `NO MATCH`.

## POST /fingerprint/liveness-check

Optical-flow passive liveness check on an ordered sequence of fingerprint camera frames (oldest → newest), using sparse Lucas-Kanade optical flow to detect the micro-tremor a live finger shows against a printed photo or screen.

**Request body**

```json
{
  "frames": ["<base64 frame 1>", "<base64 frame 2>", "..."]
}
```

2-12 frames; 6-10 at the device's native frame rate (~30fps) is recommended.

**Response**

```json
{
  "is_live": true,
  "mean_displacement": 0.83,
  "frame_count": 8
}
```

A live finger shows **0.15-2.5px** mean displacement; a printed photo or phone screen shows near-zero (< 0.15px). This threshold is an engineering estimate; calibrate against your target device and lighting before production deployment.

<Note>
  Laravel's `POST /api/fingerprint/liveness-check` wraps this call and, on a pass, mints a single-use server-held token that `POST /api/fingerprint/enroll-gallery` requires. The liveness verdict itself never travels back through the client as a spoofable boolean.
</Note>

**Errors**

| Status | Reason |
|---|---|
| 422 | Fewer than 2 frames supplied |

## POST /process-hand

Segment a whole-hand photo into up to four finger crops and extract a template from each; the contactless counterpart of `/process`. A phone photo of a hand naturally contains four fingers, matching the intended capture UX and the NISTIR-8307 finding that a four-finger slap is far more accurate than a single finger.

**Request body**

```json
{
  "image": "<base64-encoded JPEG or PNG>",
  "hand": "right",
  "domain": "contactless"
}
```

| Field | Type | Notes |
|---|---|---|
| `image` | string | Base64 whole-hand photo |
| `hand` | string | `"right"` \| `"left"`, orientation for finger naming |
| `domain` | string | `"contactless"` (default) or `"contact"`, selects the matcher; `"contactless"` uses the ONNX embedding when installed, else falls back to minutiae |

**Response**

```json
{
  "matcher": "ridgeformer_onnx",
  "domain": "contactless",
  "fingers": [
    {
      "finger_position": "right_index",
      "template": { ... },
      "quality_score": 0.71,
      "bbox": [120, 40, 260, 310]
    }
  ]
}
```

`matcher` names what actually ran, so callers can tell when they're on the placeholder/fallback rather than the calibrated embedding matcher.

**Errors**

| Status | Reason |
|---|---|
| 400 | `image` is empty or invalid base64 |
| 422 | Hand segmentation failed (fewer than the requested finger crops found) |

## POST /match-hand

Match a probe hand (up to four per-finger templates) against candidate hands, fusing the shared fingers' scores. Only fuses when at least 3 finger positions overlap between probe and candidate; below that, the hands aren't comparable and the response returns no-match rather than risk a false accept.

**Request body**

```json
{
  "probe": {
    "right_index": { ... },
    "right_middle": { ... }
  },
  "candidates": [
    {
      "patient_id": 1,
      "fingers": {
        "right_index": { ... },
        "right_middle": { ... }
      }
    }
  ],
  "domain": "contactless",
  "fusion": "mean",
  "min_fingers": 3
}
```

**Response**

```json
{
  "patient_id": 1,
  "score": 0.6231,
  "matcher": "ridgeformer_onnx",
  "fingers_used": ["right_index", "right_middle"],
  "per_finger": {
    "right_index": 0.6534,
    "right_middle": 0.5928
  }
}
```

Laravel compares `score` against the domain-appropriate threshold (`FINGERPRINT_CONTACTLESS_MATCH_THRESHOLD` for `domain=contactless`). The Python service never makes the accept/reject decision itself.

**Errors**

| Status | Reason |
|---|---|
| 400 | `candidates` list is empty |
| 400 | No candidate hand could be scored |

## POST /face/liveness

Passive anti-spoofing check on a base64-encoded face image. Two heuristics must both pass for `is_live` to be `true`:

- **Moiré score:** 2D FFT coefficient-of-variation in the mid-frequency ring; screen/printer dot patterns create periodic peaks real skin does not. Score > 25 means likely attack.
- **Specular highlight ratio:** fraction of near-white pixels; real skin has a small localised highlight, flat prints have almost none (< 0.001), phone screens produce broad overexposed regions (> 0.12).

**Request body**

```json
{
  "image": "<base64-encoded JPEG or PNG>"
}
```

**Response**

```json
{
  "is_live": true,
  "moire_score": 8.2,
  "specular_ratio": 0.014
}
```

<Note>
  Both thresholds are engineering estimates and must be calibrated via an FAR/FRR study before production deployment, same caveat as the fingerprint liveness check.
</Note>

**Errors**

| Status | Reason |
|---|---|
| 400 | `image` is empty or invalid base64 |
| 400 | Image bytes could not be decoded as JPEG/PNG |

## POST /face/process

Extract a face embedding from a base64-encoded image. Used by Laravel during both enrollment (`POST /api/face/enroll`) and hospital-wide identification (`POST /api/face/verify`).

**Request body**

```json
{
  "image": "<base64-encoded JPEG or PNG>"
}
```

**Response: face detected**

```json
{
  "face_detected": true,
  "quality_score": 0.61,
  "embedding": [0.0023, 0.1145, ...]
}
```

**Response: no face detected**

```json
{
  "face_detected": false,
  "quality_score": 0.0,
  "embedding": []
}
```

The embedding is a flat 512-dim float array. Laravel encrypts this with AES-256 before storing it in `face_templates.template`.

**Errors**

| Status | Reason |
|---|---|
| 400 | `image` is empty or invalid base64 |
| 400 | Image bytes could not be decoded as JPEG/PNG |

## POST /face/enroll

Add a 512-dim face embedding to the FAISS index for a specific patient. Called by Laravel's `FaceController` after the embedding is extracted and stored in `face_templates`.

**Request body**

```json
{
  "patient_id": 42,
  "embedding": [0.0023, 0.1145, ...]
}
```

Embedding must be exactly **512 dimensions**. Requests with a different length are rejected with HTTP 422 to prevent silent FAISS index corruption.

**Response 200**

```json
{
  "enrolled": true,
  "patient_id": 42
}
```

---

## POST /face/identify

Search the FAISS index for the closest match to a probe embedding. Retries with a doubling fetch window until at least `top_k` distinct patients are returned.

**Request body**

```json
{
  "embedding": [0.0023, 0.1145, ...],
  "top_k": 1
}
```

**Response 200: match found**

```json
{
  "patient_id": 42,
  "score": 0.8412
}
```

**Response 200: no match / empty index**

```json
{
  "patient_id": null,
  "score": 0.0
}
```

**Errors**

| Status | Reason |
|---|---|
| 422 | `embedding` is not exactly 512 dimensions |

## POST /face/match

Score a probe embedding against a list of candidate embeddings. Returns the candidate with the highest cosine similarity.

**Request body**

```json
{
  "probe": {
    "embedding": [0.0023, 0.1145, ...]
  },
  "candidates": [
    {
      "patient_id": 1,
      "embedding": [0.0019, 0.1098, ...]
    },
    {
      "patient_id": 2,
      "embedding": [0.0041, 0.2210, ...]
    }
  ]
}
```

**Response**

```json
{
  "patient_id": 1,
  "score": 0.8412
}
```

Score is cosine similarity in [-1, 1], clamped in practice to [0, 1] for valid face embeddings. Laravel applies `FaceService::MATCH_THRESHOLD` (default **0.75**) to decide match / no match.

**Errors**

| Status | Reason |
|---|---|
| 400 | `candidates` list is empty |
| 400 | `probe.embedding` is missing or empty |
| 400 | No valid candidates could be processed |

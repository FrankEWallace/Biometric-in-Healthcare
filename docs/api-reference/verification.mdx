# Verification

The verification endpoints support **hospital-wide identification** — scanning a finger without knowing the patient in advance.

---

## POST /api/verify

<Warning>
  **Deprecated.** Hospital-wide 1:N fingerprint identification lets false-accept risk grow with the patient database size. Superseded by `POST /api/verify/multimodal` (face shortlist → fingerprint confirm), which keeps the search space small. This endpoint emits RFC-8594 deprecation headers and is kept only for backward compatibility.
</Warning>

Identify a patient from a fingerprint image alone. The system matches the probe against all active fingerprints in the caller's hospital.

**Roles:** nurse — **Rate limit:** 30 req / min

**Request** — `multipart/form-data`

| Field | Type | Required |
|---|---|---|
| `fingerprint` | file (JPEG/PNG, max 5 MB) | Yes |

**Response 200 — identified**

```json
{
  "verdict": "MATCH",
  "score": 42.1,
  "patient": {
    "id": 42,
    "full_name": "Mira Kovačević"
  },
  "matched_finger": "right_index",
  "ehr": {
    "patient_id": "42",
    "name": "Mira Kovačević",
    "blood_type": "A+",
    "allergies": ["penicillin"],
    "diagnoses": [...]
  },
  "insurance": {
    "provider": "Zavod zdravstvenog osiguranja FBiH",
    "status": "active",
    "valid_until": "2025-12-31"
  }
}
```

**Response 200 — not identified**

```json
{
  "verdict": "NO_MATCH",
  "score": 0.0,
  "patient": null,
  "ehr": null,
  "insurance": null
}
```

**Response 503** — Python service unavailable

## POST /api/verify/multimodal

Hospital-wide identification using a face shortlist followed by fingerprint confirmation, instead of a single 1:N fingerprint scan. This is the recommended replacement for `POST /api/verify` — the face step narrows candidates before the more expensive fingerprint comparison runs, so false-accept risk doesn't grow linearly with the number of enrolled patients.

**Roles:** nurse — **Rate limit:** 30 req / min

---

## POST /api/verify/hand

Four-finger ("hand slap") fused verification — the mobile app captures one hand photo instead of a single finger, and the Python service segments it into four finger crops, matches each via the contactless embedding matcher, and fuses the per-finger scores (see [Python Service Endpoints](/python-service/endpoints#post-match-hand)).

**Roles:** nurse — **Rate limit:** 30 req / min

**Request fields**

| Field | Type | Default | Notes |
|---|---|---|---|
| `image` | string (base64) | — | Whole-hand photo. Required. |
| `hand` | `right` \| `left` \| `both` | `right` | `both` segments the photo as each hand server-side and keeps the better fused match — one request, one 1:N spend, one verification log. Use it when the flow doesn't ask which hand was photographed (e.g. the clerk check-in/checkout scans). |
| `gps_latitude`, `gps_longitude`, `wifi_ssid` | — | — | Optional geofence context. |

<Note>
  Advisory only (`needs_review`) until a learned contactless embedding matcher and a calibrated `FINGERPRINT_CONTACTLESS_MATCH_THRESHOLD` are installed for the deployment — it never auto-accepts on minutiae scores alone, since minutiae is non-discriminative on finger photos (RidgeBase EER ~46%).
</Note>

## GET /api/verify/logs

List verification log entries.

**Roles:** all (nurses see their own logs only; doctors see patient-centric logs)

**Query params**

| Param | Type | Default |
|---|---|---|
| `page` | int | 1 |
| `per_page` | int | 20 |

**Response 200**

```json
{
  "data": [
    {
      "id": 101,
      "patient_id": 42,
      "hospital_id": 2,
      "staff_id": 5,
      "verdict": "MATCH",
      "score": 42.1,
      "ip_address": "192.168.1.50",
      "created_at": "2025-05-01T14:22:00Z"
    }
  ],
  "current_page": 1,
  "total": 88
}
```

---

## GET /api/verify/logs/{log}

Retrieve a single verification log entry.

**Roles:** all (same scope rules as GET /logs)

**Response 200** — returns a single log entry object matching the shape above.

# Patients

All patient endpoints require authentication, the `hospital.access` network geofence, and are scoped to the caller's hospital (enforced by `PatientPolicy`).

## GET /api/patients

List active patients in the caller's hospital.

**Roles:** all

**Query params**

| Param | Type | Default | Description |
|---|---|---|---|
| `search` | string | — | Prefix match (case-insensitive) against `full_name`, `hospital_patient_id`, or `nida` |
| `page` | int | 1 | Page number |
| `per_page` | int | 20 | Results per page |

**Response 200**

```json
{
  "data": [
    {
      "id": 1,
      "hospital_id": 2,
      "hospital_patient_id": "BIH-2026-00142",
      "full_name": "Amina Juma",
      "date_of_birth": "1985-03-12",
      "gender": "female",
      "nida": null,
      "phone": "+255 61 123 456",
      "is_active": true,
      "created_at": "2026-01-15T10:30:00Z"
    }
  ],
  "current_page": 1,
  "per_page": 20,
  "total": 42
}
```

<Note>
  `jmbg` was renamed to `nida` (migration `2026_05_05_142209`) as part of the move toward a national patient identity. See [Architecture](/architecture#national-patient-identity). `hospital_patient_id` (e.g. `BIH-2026-00142`) and `patient_seq` were added alongside it as a human-readable, per-hospital-per-year identifier.
</Note>

## POST /api/patients

Register a new patient.

**Roles:** nurse

**Request body**

```json
{
  "full_name": "Amina Juma",
  "date_of_birth": "1985-03-12",
  "gender": "female",
  "nida": "12345678901234567890",
  "phone": "+255 61 123 456",
  "notes": "Allergic to penicillin"
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `full_name` | string | Yes | Max 200 chars |
| `date_of_birth` | date `Y-m-d` | Yes | |
| `gender` | enum | No | `male`, `female`, `other` |
| `nida` | string | No | Exactly 20 chars, unique |
| `phone` | string | No | Max 20 chars |
| `notes` | string | No | Max 1000 chars |

**Response 201**

```json
{
  "patient": {
    "id": 42,
    "hospital_id": 2,
    "hospital_patient_id": "BIH-2026-00142",
    "full_name": "Amina Juma",
    "date_of_birth": "1985-03-12",
    "gender": "female",
    "nida": "12345678901234567890",
    "phone": "+255 61 123 456",
    "notes": "Allergic to penicillin",
    "is_active": true,
    "created_at": "2026-05-01T09:00:00Z"
  }
}
```

```json
    "full_name": "Amina Juma",
    "fingerprints": [
      {
        "id": 7,

        "quality_score": 0.62,
        "is_primary": true,
        "is_active": true,
        "created_at": "2026-05-01T09:15:00Z"
      }
    ]
  }
}
```

## PUT /api/patients/{patient}

Update patient demographics directly.

**Roles:** admin, super_admin

<Note>
  Nurses cannot call this endpoint directly. They must submit a `POST /api/patients/{patient}/edit-requests` instead. See [Edit Requests](/api-reference/edit-requests).
</Note>

**Request body** (all fields optional, `sometimes` validation)

```json
{
  "full_name": "Amina Juma-Hassan",
  "phone": "+255 61 999 000"
}
```

**Response 200:** returns the updated patient object.

## POST /api/patients/{patient}/enroll

Enroll a **single-finger** fingerprint directly from a patient record. Base64 JSON body, not multipart. See the [Fingerprint](/api-reference/fingerprint#post-apifingerprintregister) page for the equivalent multipart pipeline.

**Roles:** nurse, admin (emergency). **Rate limit:** 20 req / min per token. Also gated by the `geofence` middleware.

**Request:** `application/json`

| Field | Type | Required | Notes |
|---|---|---|---|
| `image` | string (base64) | Yes | |
| `finger_position` | string | No | One of the 10 single-finger positions; default `right_index` |
| `is_primary` | boolean | No | Default `false`; demotes any existing primary finger for this patient |

Rejects with `422` if `quality_score < 0.30` (`PatientController::MIN_QUALITY_SCORE`).

**Response 201**

```json
{
  "message": "Fingerprint enrolled successfully.",
  "fingerprint_id": 7,
  "patient_id": 42,
  "finger_position": "right_index",
  "quality_score": 0.62,
  "is_primary": true
}
```

Re-enrolling the same `(patient_id, finger_position)` overwrites the existing template (upsert).

## POST /api/patients/{patient}/enroll-hand

Four-finger ("hand slap") enrollment. The nurse photographs a whole hand; the Python service segments it into four finger crops and returns one contactless template per finger. Laravel stores each as its own `fingerprints` row (same table, same `finger_position` enum), so the existing 1:1, 1:N, and multimodal flows work per-finger while `POST /api/verify/hand` fuses across them.

**Roles:** nurse, admin (emergency). **Rate limit:** 20 req / min per token. Also gated by the `geofence` middleware.

**Request:** `application/json`

| Field | Type | Required | Notes |
|---|---|---|---|
| `image` | string (base64) | Yes | Whole-hand photo |
| `hand` | `right` \| `left` | No | Default `right` |
| `is_primary` | boolean | No | Marks the **index finger** of this hand as the 1:N primary/gallery representative |

At least **3 of 4** fingers must pass the quality gate (`MIN_HAND_FINGERS = 3`, mirroring the matcher's fusion floor); low-quality fingers are skipped, not stored. The whole accepted set is written in one DB transaction, so a partial hand never persists half-written.

**Response 201**

```json
{
  "message": "Hand enrolled successfully.",
  "patient_id": 42,
  "hand": "right",
  "matcher": "onnx-contactless-embedding",
  "fingers": [
    { "fingerprint_id": 10, "finger_position": "right_index",  "quality_score": 0.71, "is_primary": true },
    { "fingerprint_id": 11, "finger_position": "right_middle", "quality_score": 0.68, "is_primary": false },
    { "fingerprint_id": 12, "finger_position": "right_ring",   "quality_score": 0.55, "is_primary": false },
    { "fingerprint_id": 13, "finger_position": "right_little", "quality_score": 0.41, "is_primary": false }
  ]
}
```

`matcher` reflects whatever the Python service actually ran: `onnx-contactless-embedding` if the model file is installed, otherwise the minutiae fallback name, so the client can tell when it's on the placeholder.

**Response 422:** too few usable fingers

```json
{
  "error": "Too few usable fingers. Please retake with the hand flat and in focus.",
  "usable_fingers": 2,
  "required": 3,
  "minimum": 0.30
}
```

<Note>
  This same endpoint backs the mobile app's **Retake Fingerprints** flow for already-enrolled patients. Re-enrolling a finger position overwrites its stored template. There is no separate "retake" API; the mobile UI just adds a confirmation step before calling this endpoint again. See [Mobile Overview](/mobile/overview#retake-fingerprints).
</Note>
